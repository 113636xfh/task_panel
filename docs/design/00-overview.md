# Task Panel — 需求基线（已锁定）

> 本设计稿包基于与用户的逐项确认。任何后续实现不得偏离此处结论；如需变更，先改此文件。

## 1. 定位

本地 Web 化的**任务编排与监控系统**：用户在看板创建任务 → 派给本地 Pi Agent 自动完成
`打磨(规划) → [分支问答] → 执行 → 测试验收 → 人工确认完成` 全流程。
用户通过 UI 管理看板、优先级、并发、抢占与技能/扩展。

## 2. 已锁定的工程决策

| 项 | 决定 |
|---|---|
| 技术栈 | Node/TS + Vite + React + better-sqlite3 + WebSocket |
| UI 主题 | 浅色 + 暗色双主题（暗色为默认，Linear 风格） |
| UI 设计来源 | **强制**先联网检索参考案例（见 01-ui-research.md），再定视觉规范 |
| 执行器 | 每任务一个 pi 子进程，`pi --mode rpc`（JSONL 协议），见 05-architecture.md |
| 模型接入 | 与主 Agent 完全一致：provider `local-vllm`，`http://192.168.2.15:8080/v1`，OpenAI 兼容 |
| 执行模型 | `Qwen3.8-27B-W4A16-AWQ`（180K ctx / 32K max out / reasoning / text+image） |
| 规划模型 | 同一模型，短上下文配置（maxTokens 8192、思考档 medium），规划会话结束后进程退出释放 KV cache |
| 并发 | 默认 2，用户在 UI 可调（1..N） |
| 调度 | 优先级高优先 → 同优先级按创建时间早优先；有空位即拉入；有未完成任务就持续运转 |
| 抢占 | 高优先级任务进入且无空位 → 立即 kill 低优先级 pi 进程；checkpoint 落盘；高优先级完成后按优先级恢复被中断任务 |
| 恢复 | **全量重放**留言板历史（通过 pi 持久化 session 文件重新载入，见 05 文档） |
| 分支问题 | 两模式：`人工`（挂起等用户回答）/ `自动`（默认超时后按规划智能体推荐值继续）。`等待回答` 状态不占用并发槽 |
| 阻塞决策 Blocked | 执行中 agent 遇到自己无法决断的问题时**必须停止**，写入 `work/block.json`（问题+完整背景上下文+相关文件+2-4 个具体决策项+推荐项）；任务转 `blocked` 列，不占并发槽；**默认无限等待**用户亲自拍板（不自动推进），回答后经 session resume 继续执行 |
| 验收 | 客观测试（任务内 test 命令）+ LLM 逐项验收清单评审；不通过重试，上限 **3** 次；自动验收通过后**需用户点确认**才完成 |
| 工作目录 | **创建任务时强制显式选定**：独立新目录（默认在 `workspaces/` 下自动生成名，可改）或指定已有项目目录；不选不能创建 |
| 留言板 | 完整实时展示：思考(reasoning)、工具调用(名+参数)、工具输出、消息回复；即 pi session 事件流的渲染投影 |
| 资产 | 规划/执行阶段产出的有用资料、文件，压缩（摘要+原文件引用）后以留言板"资产"区形式挂在任务下 |
| Skills & Extensions | 独立页面，**三层继承**：① 全部任务默认继承全局（`~/.pi/agent/`，只读）；② 同项目（同工作目录）任务自动继承同目录 `.pi/` 中其他任务装的技能；③ 可给单个任务手动添加（复制到该任务 workspace `.pi/`）。任务生效集 = ① ∪ ② ∪ ③ |
| 派 Agent 系统提示词 | **两组**：① **全局**：在设置页编辑保存，立即作用于所有新启动的派 Agent（**中断恢复的也按新的来**；已运行中的会话不动）；② **任务专属**：创建任务模态的补充框（可选，叠加在全局之后）。两者均只通过子进程 `--system-prompt` 参数传入，**不影响全局 pi CLI** |
| 实时用户留言 | 任务详情页底部留言框，任何时刻可发：任务活跃时走 pi RPC `steer`（当前工具轮结束后、下次 LLM 调用前生效）；任务非活跃时留言入队，合入下次启动/恢复提示词；所有留言记入留言板并全板可见 |
| 轻量化约束 | **单 Node 进程、单端口**（API + WS + 静态文件）；无重型 UI 库（自写 CSS 令牌）；SQLite WAL + 索引；事件流 100ms 合帧批量推送；不常驻多余进程（pi 进程数 = 并发数）；前端产物 gzip 后保持精简 |

## 3. 任务生命周期（状态机）

```
queued(待打磨) → planning(打磨中) → [waiting_input(待回答,仅人工模式)] → executing(执行中)
   → testing(测试验收) → awaiting_confirm(待确认) → done
   executing → blocked(阻塞待决策,用户亲自拍板) → 回答后 resume → executing
   任意活跃态 → interrupted(被抢占,可恢复) → 按优先级回到 executing(恢复,全量重放)
   planning/executing/testing → failed(重试3次超限 / 进程异常)
   任意 → cancelled(用户取消,不可恢复)
```

## 4. 优先级

- 4 级：`P0 紧急 / P1 高 / P2 中 / P3 低`（默认 P2）
- 调度与完成盘点顺序：P0 → P1 → P2 → P3；同级按创建时间
- 抢占仅由 **严格更高优先级** 触发（P0 可抢占 P1/P2/P3，P1 可抢占 P2/P3，依此类推）

## 5. 范围（MVP 全核心闭环）

P0 骨架 → P1 核心闭环（含分支问答、自动验收、重试、Skills 页面）→ P2 抢占与体验增强。
见 06-roadmap.md。
